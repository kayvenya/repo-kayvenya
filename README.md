# Монитор экскурсий музея «Собрание»

Скрипт проверяет страницу [записи на экскурсии](https://mus-col.com/contacts/tours.php) на серверах GitHub Actions и отправляет уведомления в Telegram. Постоянно включённый компьютер или телефон не нужен: Android только получает сообщения через Telegram.

## Что делает монитор

Workflow `Museum Tours Monitor` запускается каждый календарный день, включая выходные и праздники, каждые пять минут с 12:50 до 14:30 по Москве. Всего запланирована 21 проверка в день.

Время телефона не используется. Cron-расписание записано в UTC, а дата состояния и текст отчётов рассчитываются в часовом поясе `Europe/Moscow`. Смена часового пояса или неверные часы на телефоне не влияют на мониторинг.

Страница классифицируется так:

- `NO_TOURS` — только если полный нормализованный блок страницы совпал с зафиксированным текстом об отсутствии экскурсий;
- `TOURS_AVAILABLE` — найдено содержимое экскурсии с элементом записи; бот немедленно отправляет текст и ссылку;
- `UNEXPECTED_FORMAT` — страница загрузилась, но её формат не удалось уверенно распознать. Бот отправляет диагностический фрагмент, а следующие проверки продолжаются по расписанию.

Одинаковый неизвестный формат не дублируется в течение дня. Если содержимое изменится, придёт новое диагностическое сообщение: это помогает не пропустить экскурсию в ещё неизвестной вёрстке.

## Ежедневный отчёт

Workflow `Museum Tours Daily Report` пробует сформировать отчёт в 14:40 и 14:50 МСК, когда все проверки уже завершены. В 15:05 МСК выполняется финальная попытка; отсутствующие и незавершённые запуски считаются ошибками.

- 21 успешная отрицательная проверка: сообщение, что до 14:30 экскурсии не появились.
- 1–4 ошибки: сообщение указывает число успешных и ошибочных проверок, не утверждая, что экскурсии непрерывно отсутствовали.
- 5 и более ошибок из 21: доля ошибок превышает порог `20%`, поэтому приходит предупреждение, что надёжно проверить страницу не удалось.
- Если экскурсия была найдена, отрицательный итог не отправляется. Предупреждение о 5 и более ошибках всё равно отправляется.

Ошибка одного запуска или отправленное предупреждение не отключает расписание. Следующие проверки запускаются GitHub независимо.

## Секреты GitHub

В настройках репозитория должны существовать два Actions secrets:

```text
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
```

Путь: **Settings → Secrets and variables → Actions → Repository secrets**.

Токен и chat ID не записываются в исходный код, файл состояния или логи. Файл `state/status.json` содержит только московскую дату, флаги отправленных сообщений и хеши уже показанных неизвестных форматов.

Для служебных коммитов состояния workflow требуется право записи. Если шаг `git push` получает ошибку доступа, открой **Settings → Actions → General → Workflow permissions**, выбери **Read and write permissions** и сохрани настройку.

## Первая проверка

1. Открой вкладку **Actions** репозитория.
2. Выбери `Museum Tours Monitor`.
3. Нажми **Run workflow**.
4. Выбери режим `test-notification` и запусти workflow.
5. В Telegram должно прийти сообщение:

```text
✅ Тест: монитор экскурсий может отправлять сообщения.
```

После этого можно вручную запустить режим `check`. При текущем известном отрицательном формате сообщение о доступности не отправляется. Если сайт изменил вёрстку, придёт предупреждение `UNEXPECTED_FORMAT`, но расписание продолжит работу.

## Сообщения и состояние

При первом обнаружении экскурсии за московский день бот отправляет заметное сообщение со ссылкой на страницу. Повторные проверки этого же дня его не дублируют. На следующий московский день начинается новый цикл.

После успешной отправки workflow коммитит только `state/status.json` с сообщением:

```text
chore: update museum monitor state
```

Обычные отрицательные проверки не создают коммитов. Если Telegram не подтвердил доставку, состояние не меняется и следующий запуск повторит отправку.

## Как остановить

Чтобы временно остановить систему:

1. Открой **Actions → Museum Tours Monitor** и выбери **Disable workflow**.
2. Открой **Actions → Museum Tours Daily Report** и также выбери **Disable workflow**.

Отключить нужно оба workflow. Для окончательного удаления можно удалить оба файла из `.github/workflows/`. Экстренно прекратить только Telegram-отправку можно отзывом токена через `@BotFather`, но штатный способ — отключение workflow.

## Локальная проверка

Сторонние Python-пакеты не требуются:

```bash
python3 -m unittest discover -s tests -v
PYTHONPYCACHEPREFIX=/tmp/museum-tours-pycache python3 -m py_compile src/monitor.py
```

Сетевые запросы имеют таймауты. GitHub может задерживать или пропускать отдельные cron-запуски; такие случаи отражаются в ежедневной статистике ошибок.
